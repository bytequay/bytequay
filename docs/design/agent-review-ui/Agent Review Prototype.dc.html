Not introduced: no new UI framework, icon library, theme, or generic comment framework. Genuinely missing pieces that production will need: a focused “navigate to finding range” target in the diff viewer (open file, unfold, scroll, highlight R118–R131); a durable draft item linked to a finding (the current pending-comment array is renderer-held); and capability flags from the task service so Steer now / Run next / subagents render only when the provider lane supports them. Handlers are separate from appearance: Ask agent, Resolve locally, Add to my review, Post comment now, and Open discussion are review-service calls; they never reuse the GitHub Reply/Resolve/Submit callbacks.
Checked in this prototype: keyboard — every control is a real button/textarea with visible focus ring, fold buttons expose aria-expanded, tabs use role=tab/aria-selected, Esc closes a composer, ⌘/Ctrl+Enter sends. Overflow — long file paths ellipsize from the left (path tail visible), evidence blocks wrap and scroll at 180px, thread bodies wrap with word-break; the 600px pane wraps the tab row, status strip and action rows instead of clipping.
