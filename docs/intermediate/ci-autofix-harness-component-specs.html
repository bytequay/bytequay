①CI Probe

The only component that talks to CI — a thin generic shell over the ForgeAdapter.

Boundary

Program

Answers one question — "for this PR's latest completed run, which jobs failed and what are their logs?" — and nothing about why. Delegates every forge call to a pluggable ForgeAdapter (GitHub Actions / GitLab CI / Buildkite).

Data structures

@dataclass(frozen=True)
class Run:
    id: int; head_sha: str; status: str; conclusion: str | None; jobs: list["Job"]
    def all_green(self): return all(j.conclusion in ("success","skipped") for j in self.jobs)
    def failed_jobs(self):
        agg = kb.aggregators()                    # derived from needs: graph, not a name
        return [j for j in self.jobs
                if j.conclusion in ("failure","cancelled") and j.name not in agg]

@dataclass(frozen=True)
class Job: id:int; name:str; conclusion:str; started_at:str

Code (adapter-backed)

class CIProbe:
    def __init__(self, forge, store): self.forge, self.store = forge, store
    def latest_run(self, pr) -> Run:  return self.forge.latest_run(pr)
    def logs(self, job) -> str:
        return self.store.get_log(job.id) or self.store.put_log(job.id, self.forge.logs(job))
    def wait_for_next(self, pr, after, poll=90):
        while True:
            r = self.latest_run(pr)
            if r.id != after and r.status == "completed": return r
            sleep(poll)

Edge cases (earned on a real bump PR)

  • Pagination is mandatory — large matrices run to the hundreds; the failures can live on page 3. The adapter stitches pages.
  • cancelled ≠ failed — a leg cancelled because a sibling failed; inspect its log if present, else follow siblings.
  • Skip aggregators — the "everything passed" job mirrors the worst sibling; it's identified from the bootstrap needs: graph, never by name.
Failure handling

Transient forge errors → retry with backoff; never let one 5xx kill the loop. A run still in_progress → return it; the Orchestrator keeps waiting.

Tests

Recorded JSON fixtures: a 3-page jobs response and a mixed success/cancelled/failure set → assert failed_jobs() excludes aggregators, includes cancelled, and pagination stitches all pages.

②Log Parser

Raw log → typed Failures. Generic engine; the failure grammar comes from the EcosystemPack.

Boundary

Program

Pure, deterministic, no network. Its hardest job is normalization — so the same bug across two runs yields one stable signature (the dedupe + idempotency key).

Pipeline

def parse(log: str, pack: EcosystemPack) -> list[Failure]:
    out = []
    for ex in pack.extractors:             # surefire | pytest | jest | cargo …
        for h in ex.find(log):
            excerpt = window(log, h.line, before=2, after=40)
            out.append(Failure(module=pack.module_of(h), test_class=h.cls, test_method=h.method,
                               signature=normalize(pack.first_cause(excerpt)), log_excerpt=excerpt))
    return dedupe(out)

Normalization — the crux

_SCRUB = [
    (re.compile(r"_[0-9a-f]{6,}\b"), ""),          # random suffixes: foo_5pf6yz → foo
    (re.compile(r"/tmp/\S+"), "<tmp>"),
    (re.compile(r"\b\d{4}-\d\d-\d\dT[\d:.]+"), "<ts>"),
    (re.compile(r":\d+\)"), ":<n>)"),               # stack-frame line numbers
    (re.compile(r"\b\d+(?:\.\d+)?\s*(?:ms|s|sec|secs)\b"), "<dur>"),  # elapsed times: "Time elapsed: 0.052 s"
    (re.compile(r"(?:@|0x)[0-9a-f]{6,}\b"), "<addr>"),  # identity hashes: Row@1f3a9c2b
]
def normalize(s):
    for p, r in _SCRUB: s = p.sub(r, s)
    return " ".join(s.split())[:200]

Without this, two runs of the same failure look like two bugs. first_cause walks the Caused by: chain to the root exception — the diagnostic signal, not the outer wrapper.

The scrub list is load-bearing and incomplete by default. Every unscrubbed volatile token silently breaks two things at once: the dedupe key and the KB matcher, so candidate rules never reach their promotion threshold and the harness re-pays the agent for a failure it has already solved. The two that bite first are test-runner elapsed times (Time elapsed: 0.052 s — present on every surefire failure line) and identity hashes (Row@1f3a9c2b). Treat the list as per-ecosystem and grow it from real logs; the acceptance test below is what keeps it honest. Scrub only incidental tokens — assertion values like expected:<[5]> but was:<[7]> must survive, or two different bugs collapse into one signature.

Edge cases

  • Multi-failure classes (“Failures: 19”) — one Failure per failure line, then dedupe by signature so N identical errors become one actionable item.
  • Interleaved parallel logs — anchor on the failure line, read forward, tolerate interspersed warnings.
  • No test id for build errors — module comes from the file path token instead.
  • Warnings ≠ errors — deprecation/warn lines must be excluded; they flood logs.
Tests

Golden-file tests over redacted real logs → assert exact (signature, module) tuples; a test that two runs of the same failure produce an identical signature.

③Classifier engine

Generic matcher over learned KB rules. Holds no rules of its own.

Boundary

Program

Evaluate a Failure against the KB's active rules; return a bucket or UNKNOWN. The engine never changes per project.

def classify(f: Failure, kb: RuleStore) -> tuple[Bucket, Rule | None]:
    for r in kb.active_rules_by_specificity():   # most-specific first; INFRA/defer highest
        if r.matcher.test(f):
            kb.touch(r, f)                        # record a hit → feeds promotion + audit
            return r.bucket, r
    return Bucket.UNKNOWN, None                   # → learning path (⑤ + KB write)

Ordering & safety

  • Specificity, not scoring — explicit priority; a narrow pattern beats a broad one. Auditable, no ML.
  • Defer beats fix — INFRA / bootstrap rules rank highest so a recipe-rule can't override "don't touch an unreproducible job."
  • Only active rules match — a freshly-learned candidate is recorded but can't misroute before it's confirmed.
⚠ Bias to UNKNOWN, never to a wrong route

A missed match costs one agent call; a wrong match risks a wrong fix. When no active rule is confident, fall through to ⑤ and let the encounter teach a rule.

Tests

Table-driven (signature/excerpt → expected bucket); a regression that INFRA beats a fixable bucket when both could match; an unknown line returns UNKNOWN.

⑤Diagnosis Service · Agent

The one non-deterministic box: a bounded agentic tool-use loop producing a validated Diagnosis. Proposes only.

Shape

Agent

A pure advisory function (Failure, read-only tools, conventions) → Diagnosis. It reasons and proposes; it never touches the worktree, git, or CI. That's what lets you swap the model or drop in a human without touching the loop.

class DiagnosisService:
    def diagnose(self, f: Failure, repo) -> Diagnosis:
        tools = self.mk_tools(repo)                 # read-only, scoped to this repo
        raw = self.llm.run_tool_loop(build_prompt(f, self.conventions),
                                     tools.specs, max_iters=self.budget)
        return parse_and_validate(raw, repo)         # harness-side gate (below)

The LLM layer (tool-use loop, model, caching) is abstracted — provider-agnostic by design.

The tools — read-only, the agent's entire world

class RepoTools:
    def read_file(path, start=None, end=None): ...   # a file or a line range
    def grep(pattern, glob="**/*"): ...            # find callers / missed consumers
    def git_show(ref, path): ...                    # a prior/other version
    def git_log(grep=None, n=20): ...              # candidate fixup targets
    def oss_diff(commit): ...                       # the ORIGINAL upstream commit (via link convention)
    def candidate_targets(hint): ...              # real commit subjects only
  • oss_diff is the highest-signal tool — the seam is almost always "upstream changed a shared thing; a fork-only consumer wasn't updated." Showing the original commit turns guessing into diagnosis.
  • grep finds the missed consumer; candidate_targets returns real commits so the agent can't invent a subject.
  • Tools return bounded output (line ranges, capped hits) — a huge file doesn't blow context.

Prompt structure (first two layers cacheable)

SYSTEM (cached): role · invariants (minimal-diff, semantic-owner target, "propose don't apply")
                · strict output schema · tool list + when to use each (lead with oss_diff)
                + KB-derived project hints (sharpen as the KB grows)
USER (per failure): the Failure + "work in this order: culprit via oss_diff/grep →
                    smallest fix → target from candidate_targets → generalization → self-check"

Confidence — a rubric, not a vibe

rubric = { culprit_identified, mechanism_explained, fix_is_minimal,
           target_from_candidates, anchors_unique, reversible_low_blast }  # all bool
confidence = weighted(rubric)     # all-true→~0.9; culprit unknown→capped ~0.4
# harness gates: confidence < θ (0.75) or needs_human → escalate.
# confidence decides WHO reviews — never WHETHER to trust. Every fix still hits the Verifier.

Generalization — a good signature_pattern, self-tested

  • Produce a regex matching this failure's signature; state which tokens are stable vs incidental.
  • Self-test: it must match the current signature and not match a sample of unrelated ones (passed in). Over-broad is the danger.
  • The harness re-validates and stores it as candidate — K hits or human approval before it's active.
Harness-side validation — makes a stochastic box safe
def parse_and_validate(raw, repo) -> Diagnosis:
    dx = json_or_reject(raw)                                    # schema-valid only
    assert dx.target_subject in real_subjects(repo, dx.target_subject)  # no invented target
    for e in dx.edits: assert repo.read_file(e.path).count(e.find) == 1  # unique anchor
    assert re.search(dx.signature_pattern, cur_sig) and \
           not any(re.search(dx.signature_pattern, o) for o in unrelated)  # not too broad
    return dx
Escalation & tests

Escalate when culprit unfound in budget, the fix is a genuine trade-off, or validation fails twice — carrying the partial rationale + tool transcript. Test via an eval set of recorded failures → score culprit/target match, edit-locality, and "did the Verifier pass"; track pass-rate across model/prompt changes.

⑥Fix Applier

Turn a proposed fix into staged worktree changes — all-or-nothing, or refuse.

Boundary

Program

Apply exactly what was specified (agent Edits or a recipe's side-effects). No commit, no verify, no judgment.

def stage(self, edits, target) -> FixResult:
    planned = {}
    for e in edits:                                # 1. build all new contents in memory FIRST
        text = planned.get(e.path) or read(e.path)
        if text.count(e.find) != 1: raise Ambiguous(e.path)   # exactly-one anchor
        planned[e.path] = text.replace(e.find, e.replace)
    for p, c in planned.items(): write(p, c)         # 2. only if ALL anchors valid
    return FixResult(sorted(planned), target,
                     verify_cmds=self._infer_verify(planned), source="agent")

def stage_recipe(self, recipe, f) -> FixResult:
    before = git.snapshot()
    fr = recipe.apply(repo, f)                        # may run a generator / rename
    return replace(fr, files_changed=git.changed_since(before))

Edge cases (earned on a real bump PR)

  • Non-unique anchor → hard refuse. 0 or 2+ matches is an error the agent must fix, never a first-match guess.
  • All-or-nothing. Validate every anchor, then write — a bad 3rd edit never leaves the first two half-applied.
  • Recipes produce files, not edits — capture the delta by snapshot; renames show as delete+add (⑧ re-detects renames).
  • Never stage outside the fix — files_changed is this op's delta only, so ⑧'s path-scoped commit stays clean.
Tests

A 2-edit set whose 2nd anchor is duplicated → assert nothing written; a rename recipe → files_changed lists old+new; _infer_verify table tests.

⑦Verifier

Prove a staged fix the way CI does — by executing a VerifyProfile derived from CI, not hardcoded commands.

Boundary

Program

Given a staged worktree, run the project's own checks scoped to the change. Holds no commands — executes CI-derived templates + learned env deltas.

def run(self, fix: FixResult, prof: VerifyProfile) -> Result:
    for verb in verbs_for(fix.files_changed):        # style/build/test/regen — generic verbs
        for tpl in prof.steps.get(verb, []):          # the ACTUAL CI step(s)
            cmd = strip_unreproducible(scope(tpl, fix))
            ok, log = exec(cmd, env=prof.effective_env())
            if not ok and is_env_failure(log):        # 401 / wrong runtime / missing module
                prof.learn_env_delta(log); ok, log = exec(cmd, env=prof.effective_env())
            if not ok: return Result(False, cmd, tail(log, 60))
    if "regen" in verbs_for(fix.files_changed): return self._regen_idempotent(fix)
    return Result(True)

def _regen_idempotent(self, fix):        # 0-diff proof for regenerated resources
    run_generator(); drift = git.diff_stat(exclude=fix.files_changed)
    return Result(drift == "", reason=drift)

Env is derived + learned, never hardcoded

  • Derived at bootstrap: runtime version from setup-*, flags from build config.
  • Learned on first env-failure: auth to mint, runtime to pin, module flag to add → an env_delta (candidate→confirmed).
  • AuthProvider adapter supplies credentials; secrets never inlined or printed.
⚠ Run CI's real steps — don't approximate

Because the local check is the CI step, "green locally, red in CI" (a skipped style profile that hid 7 failures) can't recur. Faithful-first; only scope to the changed module; if a scoped run diverges from CI, mark the verb non_scopable.

Not locally reproducible · Tests

Cloud/special-hardware steps are stripped, not faked → escalate. Test: a fixture with a style violation fails the style verb; a deterministic generator passes regen-idempotent, a timestamp-injecting one fails with the drift; a cloud test id returns not-locally-reproducible without invoking the build.

⑧Git Safety Layer

The crown jewel — every history mutation, safe by construction. 100% Program; the agent has no method here.

The one invariant

Program

backup → mutate → assert the diff is exactly what was intended → else hard-restore. Nothing trusts an exit code. Driven by a configurable HistoryPolicy (fixup-per-pick is one; squash is another).

The safety primitive

def _guarded(self, mutate_fn, expect="EMPTY"):
    self._clear_stale_locks()
    before = git("rev-parse HEAD"); git(f"branch -f backup/{ts()} {before}")
    try:
        mutate_fn()
        got = git(f"diff {before} HEAD --stat")
        if expect == "EMPTY": assert got == "", f"TREE DRIFT:\n{got}"  # ← the catch
    except Exception:
        git("rebase --abort"); git(f"reset --hard {before}"); raise  # always restore

Tight range — never master

def _internal_base(self, *subjects):
    shas = [sha(s) for s in subjects]
    # max, NOT min: `rev-list --count X..HEAD` grows as X gets older, so the
    # earliest target is the one with the LARGEST count. Taking min picks the
    # newest target and silently leaves earlier fixup! commits outside the
    # rebase range, unsquashed, on the branch you hand off.
    earliest = max(shas, key=lambda s: int(git(f"rev-list --count {s}..HEAD")))
    return f"{earliest}^"   # parent of the earliest touched commit — no external ref can leak in

commit_fixup — path-scoped, exact target

def commit_fixup(self, files, target_subject):
    exact = [sha for sha, subj in log_subjects(target_subject) if subj == target_subject]
    assert len(exact) == 1, f"target resolves to {len(exact)}"       # exact, not substring
    git(f"commit --fixup={exact[0]} -- {shlex.join(files)}")          # NEVER a bare commit

move_hunk — relocate a change between commits (the reviewer fix)

def move_hunk(self, files, from_subject, to_subject):
    A, B = sha(from_subject), sha(to_subject); H = extract_hunk(A, files)
    def do():
        start_rebase_with_edits(f"{A}^", [A, B])
        while (stop := current_stop()):        # re-check each stop (a conflict can skip one)
            op = H.inverse() if stop == A else H.forward()  # re-add at A / remove at B
            for f in files: apply_unique(f, op)   # unique-anchor find/replace
            amend_paths(files)
            if "CONFLICT" in git("rebase --continue"): resolve_or_abort(files)
    self._guarded(do, expect="EMPTY")             # net-neutral: only ownership moved

def resolve_or_abort(files):
    for f in conflicted(files):
        if is_adjacent_insertion(f): take_union(f)  # keep BOTH distinct blocks
        else: raise Conflict(f)                     # semantic overlap → abort → escalate
    if not compiles(files): raise Conflict("union did not compile")  # union is compile-verified
    git(f"add -- {shlex.join(files)}")

divergence — fetch first, always

def divergence(self, branch):
    git(f"fetch origin {branch}")                 # ← NEVER skip: the stale-ref bug, twice
    O = f"origin/{branch}"
    behind = int(git(f"rev-list --count HEAD..{O}"))
    if behind > 0:                              # parallel work pushed — never force alone
        return DivergeReport(behind=behind, action="ESCALATE",
                             push_hint=f"git push --force-with-lease origin {branch}")
    return DivergeReport(behind=0)
Lock & zombie safety

Clear a stale index.lock only when there's no rebase-merge/rebase-apply dir and no live git process, and HEAD is on the expected branch — the exact checks worth running by hand before an rm.

Failure/recovery · Program-only · Tests

Every method is crash-safe: backup/<ts> is kept on failure; a recover() resets to the newest backup and aborts any in-progress rebase. The agent can read git but has no method here — it cannot rewrite history. Test: a rebase that alters a file → _guarded raises + restores; a move_hunk round-trip → diff(before,HEAD)==""; origin-ahead-by-1 → ESCALATE + correct push hint; a planted stale lock (no rebase dir) → cleared, with a rebase dir → refused.
